Pi Pilled

I’ve always thought that developers loving their tools was a form of Stockholm Syndrome, but over the past year few tools have gotten more admiration than Pi, which just released version 1.0 this past week.

If you haven’t heard of it or used it, Pi is a minimalist agent harness written in TypeScript whose original claim to fame was powering OpenClaw. Like most harnesses, it has a TUI, CLI and SDK but I never really “got” why developers liked it so much. Then I remembered how many developers I’ve met who exclusively wear conference t-shirts and cargo shorts, that can’t wait to tell you about their custom Neovim config. For these developers, Pi is perfection.

Why developers love Pi:

Of the major harnesses that support multiple models, only OpenCode and Pi are open source. And we all know open source is developer catnip. But what sets Pi apart is your ability to customize the tool. Its core is intentionally minimal and until v0.99, it didn’t even support MCP. Instead, it exposes an extension API which lets you install custom packages, or more impressively, lets you extend Pi directly via a prompt.

What’s new in Pi 1.0

  • Pi Durable: The Pi team created a new package that allows developers to create and deploy long-running agents to the cloud that can survive crashes. It handles durable storage and memory for your agent via SQLite and JSONL, and provides a small adapter that allows you to connect to whatever runtime and storage solution you’re using.

  • Codemode: This new Pi feature allows models to generate scripts that run in a QuickJS sandbox. These scripts can call Pi or MCP tools directly and transform the results, saving you precious tokens. It can even be used to run other non-LLM models such as classifiers and image models.

  • Virtual models: Pi lets you create “virtual models” you can select with the /model selector, but under the hood, they’re just extensions. These extensions can use a classifier or some other mechanism to route queries to different models, giving you control over the speed and cost of each type of query.

Bottom line: If you’re the type of developer who keeps your dotfile config on GitHub and you haven’t tried Pi yet, what are you even doing with your life? Also maybe take a shower today.

Spot the Bug: Solution

Spot the Bug - Presented by webmcp-react

When using the Array.sort method, the compare function should return a number, not a boolean. Returning a negative number will sort the first item before the second, a positive number will sort the second item before the first, and returning 0 will leave the items in the same order.

const products = [
  { name: 'Grapes', price: 2 },
  { name: 'Banana', price: 1 },
  { name: 'Apple', price: 3 },
  { name: 'Cherry', price: 2 },
  { name: 'Date', price: 1 }
];

products.sort((a, b) => a.price - b.price);
