Parcel’s Big Rust Wave

Every JavaScript build tool eventually goes through the same five stages of grief: denial, benchmarks, bargaining, porting a couple modules to Rust, and finally accepting that Node is the problem.

Parcel just hit stage five. The Parcel 3 alpha came out this week, and it’s a ground-up Rust rewrite with “no dependency on Node at all.” The CLI, dev server, transformers, bundler, and optimizers all live in a single binary under 30 MB, which is down from a ~120 MB install for v2 and hundreds of npm dependencies.

Devon Govett and the Parcel team have been Rust-curious for a while now with Lightning CSS and building on SWC, but they’re finally going full Rust for two reasons: 1) Parcel’s JavaScript core was always limited by its inability to share memory across threads, and 2) AI is very good at writing painfully tedious Rust code.

Here’s what Parcel’s big rewrite gets you:

  • Up to 100x faster cold builds. React Spectrum’s docs site went from 87.6s to 810ms, and memory usage fell 2.5x to 6.6x across their benchmarks.

  • No more disk caching. Caching makes sense when the underlying work is slow. When it’s fast, the invalidation tracking becomes the bottleneck and a bug factory. v3 keeps in-memory rebuilds and otherwise just rebuilds from scratch.

  • Plugins are native now. It exposes a stable C interface, so you can write plugins in Rust, Go, or Swift. And simple JS/TS plugins run in an embedded QuickJS runtime.

Bottom Line: Parcel is arguing that once cold builds are fast enough, most of the complexity we’ve piled onto bundlers (cache layers, invalidation tracking, massive plugin ecosystems) stops being worth it. If they’re right, Vite and Rspack might have a very loud new neighbor in the build tool thunderdome.

class Queue {
  constructor() {
    this.list = [];
    this.length = 0;
  }

  enqueue(value) {
    this.length++;
    this.list.push(value);
  }

  dequeue() {
    if (this.length === 0) return;
    this.length--;
    return this.list.shift();
  }

  peek() {
    return this.list[this.list.length - 1];
  }
}

Spot the Bug: Solution

Sponsored by Fingerprint

A queue is first in, first out, so peek() should return the first item, not the last.

class Queue {
  constructor() {
    this.list = [];
    this.length = 0;
  }

  enqueue(value) {
    this.length++;
    this.list.push(value);
  }

  dequeue() {
    if (this.length === 0) return;
    this.length--;
    return this.list.shift();
  }

  peek() {
    return this.list[0];
  }
}
