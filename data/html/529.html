A Eulogy for Deno

When I wrote about Cloudflare’s acquisition of Deno last week, I glossed over the fact that Deno is… dead. So today, we give Deno a proper send-off.

In remembrance:

On behalf of the JavaScript community, I just want to start by thanking all of you for being here today. Deno always had a special place in our hearts. It was the main topic for the very first issue of Bytes, and was our “Main Thing” 12 times. I’m really going to miss farming content from Deno.

Born in 2018 out of a strong sense of parental guilt, Deno was raised right. It was taught the value of consent, always asking for permission to use the network or read .env files. And from an early age, it stayed pure from npm, keeping its dependencies decentralized. It also brought the JavaScript ecosystem a real stdlib (inspired by Go), freeing developers from installing packages like left-pad.

But over time Deno lost its way. It wanted to fit in with the rest of the ecosystem and was tempted by things like “adoption” and “market share”, becoming more and more like its older brother Node. And while it eventually succumbed to these pressures, let’s not forget some of the lessons Deno taught us.

Deno’s legacy:

  • Security: Scoped permissions became a core runtime feature, helping inform Node’s opt-in permission model, which stabilized in 2025.

  • Web APIs on the server: Its embrace of browser-standard APIs like fetch and Web Streams, alongside its role in establishing WinterCG, helped improve interoperability across JavaScript runtimes.

  • TypeScript native runtime: Running TypeScript without a separate build setup became an expectation, with Bun and Node now supporting that experience.

Bottom line: Deno, even though I only installed you twice and never used you in production, I loved you. And to Ry, please win that lawsuit with Oracle. Oh, and you’re a good dad ❤️.

Spot the Bug: Solution

Spot the Bug - Presented by Orkes

When you call array.push, it doesn’t return the updated array, but rather the updated length of the array with the new item. That means you can’t chain the .sort() call to the end, since the result of .push is a number.

To fix this, call array.sort() after the .push call.

function addAndSort(array, element) {
  array.push(element);
  return array.sort();
}
