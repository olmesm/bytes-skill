Pouring One Out for PHP

It’s been a rough week for PHP developers, and since there are about 24 loyal Laravel / WordPress devs who read Bytes, we’re dedicating this issue to commiserating with our <?= brethren ?>.

So what happened? Well, if you don’t know, you probably have healthier internet consumption habits than me, but the TL;DR is that PHP got hacked… badly. The vulnerabilities are called php2shell, and they can give attackers access to a shell on a vulnerable server, where they could access your database, API keys, and environment variables… or just mine for crypto (if that’s still a thing). Pretty bad, especially considering that the flaws are in PHP itself, putting unpatched servers at risk regardless of the application running on them.

How does php2shell work?

First, an attacker sends a multipart/form-data POST request to any page on the server, hiding a shell command and the fake data structures needed to execute it in the field values. The request is padded with a huge number of headers and thousands of empty file fields, with content-length conveniently omitted. PHP runs out of memory while parsing the request, leaving the malicious payload in memory when the shutdown routine runs.

Then, during shutdown of that same request, the cleanup code walks the half-built state, follows a pointer the attacker planted in it, and executes the payload with the server’s own permissions 😬.

What’s the fix?

PHP sites need to update to a patched release: 8.5.12, 8.4.27, 8.3.36, or 8.2.35. Which, if we’re being honest, could be a challenge for sites still running legacy versions. Cloudflare’s WAF protections can block known exploit attempts while those sites patch, but PHP says updating is the only complete fix.

Where do we go from here?

While it might be tempting to breathe a sigh of relief, our day of reckoning as JavaScript developers is coming because Node.js just got hit with a high-severity CVE impacting its Brotli decoder. And if I had to guess, this is only the beginning of this new era of software development which is so fun. I love it here.

Bottom line: Looks like your PM is going to have to drop all the features they wanted to ship in Q4 in order to keep up with all the security patches coming down the pipe.

Spot the Bug: Solution

Spot the Bug – Presented by Run by Apify

The code will throw a TypeError because the treeDepth function is not handling the base case. The base case should be when the node is null, in which case the function should return 0.

class TreeNode {
  constructor(value) {
    this.value = value;
    this.left = null;
    this.right = null;
  }
}

function treeDepth(node) {
  if (node === null) return 0;
  let leftDepth = treeDepth(node.left);
  let rightDepth = treeDepth(node.right);
  return Math.max(leftDepth, rightDepth) + 1;
}

let root = new TreeNode(1);
root.left = new TreeNode(2);
root.right = new TreeNode(3);
root.left.left = new TreeNode(4);
root.left.right = new TreeNode(5);

console.log("Depth of the tree:", treeDepth(root));
