## SolidJS gets an SSR Glow-up

[The release notes](https://github.com/solidjs/solid/releases/tag/v1.3.0) for SolidJS v1.3 are titled “Spice Must Flow” — a line from *Dune* that could be intended as a metaphorical critique of the over-commodification of OSS frameworks by venture capitalists and big tech, along with the larger systemic issues plaguing our current version of late stage techno-capitalism.

Or maybe the SolidJS team just likes Dune. [I guess we’ll never know.](https://www.youtube.com/watch?v=GzlKja1ySzo&t=10s)

**Quick Review:** SolidJS is a new-ish JavaScript framework that got [a lot of buzz](https://risingstars.js.org/2021/en#section-framework) in 2021 because of its *[why-not-both](https://www.youtube.com/watch?v=vqgSO8_cRio&t=5s)* approach of providing “all the flexibility of React and the simple mental model of Svelte.”

**What does that actually mean?** Solid has all your favorite React features like Fragments, Context, Concurrent Rendering, SSR, and more — but with no Virtual DOM. Instead, every part of Solid (including its renderer) is built on the same foundation of composable “reactive primitives” that are very extensible and [very fast.](https://krausest.github.io/js-framework-benchmark/current.html)

This 1.3 release is all about beefing up Solid’s SSR capabilities. Here’s how:

- **[HTML Streaming](https://www.youtube.com/watch?v=8hlo9uPrpr4)** — As soon as the HTML is available to the user, it’s immediately streamed and inserted (even if the JavaScript bundle hasn’t loaded yet), thanks to a new `renderToStream` API.
- **Isomorphic Error Boundaries** — Makes it a lot easier to catch and solve rendering errors for all rendering methods (including streaming).
- **Multiple Async Hydration Routes** — You can now pass a unique `renderId` on all of Solid’s server rendering methods and to the hydrate function. This isolates all hydration and lets you server render and hydrate multiple Solid apps on the same page.

**Bottom Line:** If OSS is the spice, does that make all of us the giant worms?

## Stream is how smart developers build chat apps

Building a chat app from scratch in 2022 is like trying to make [Pop-Tarts from scratch](https://www.youtube.com/watch?v=jYqRiKu7gY0) – overly complex and completely unnecessary thanks to modern technology.

That’s because most developers just [use Stream](https://getstream.io/chat/trial/?utm_source=Bytes&utm_medium=newsletter_content_ad&utm_content=Developer&utm_campaign=Bytes_Dec2021_ChatTrial&ck_subscriber_id=890565875). It’s the #1 chat-messaging and activity feed platform in the world – because it handles all of the mess that comes with building chat apps for you.

**bUt WilL iT SCaLe?** Don’t ask me, ask Match.com – they use Stream to let their 21.5 million members send each other heartfelt messages like, *“You up?”* every single day. So next time you drunkenly message that person who ghosted you 7 months ago, you can thank (or curse) Stream for making it all possible.

Adobe, Imgur, SoundCloud and a bunch of other companies have built apps with Stream too. Chances are, you’ve probably already used Stream’s chat without even realizing it 🤯.

[Check out this tutorial](https://getstream.io/chat/trial/?utm_source=Bytes&utm_medium=newsletter_content_ad&utm_content=Developer&utm_campaign=Bytes_Dec2021_ChatTrial&ck_subscriber_id=890565875) to see how easy it is to build a React chat app that leverages Stream’s Chat API and their React Components. The API is surprisingly flexible, which means you can build pretty much any chat experience you’d ever need.

## The State of GraphQL in 2022

2021 was quietly a big year for the GraphQL world. Let’s take a look at what went down and where we’re at in 2022.

**What the REST is GraphQL?** It’s an API query language created by ~~Lord~~ *Lee* Byron and his (old) team at Meta to share an API between web and mobile apps. Instead of using different URLs for each API, GraphQL uses a single endpoint and has the exact data you want sent with the request.

Like most of the React team, GraphQL couldn’t wait to escape from ~~Facebook~~ Meta — and it finally did so in 2018 with the formation of the GraphQL Foundation. Since then, it’s spawned a lively community with [lots](https://graphcdn.io) of [companies](https://www.the-guild.dev) trying to [commercialize](https://www.apollographql.com) GraphQL, many [services](https://supabase.com) supporting GraphQL, and *many* [packages](https://github.com/chentsulin/awesome-graphql#implementations) for implementing GraphQL.

What big things happened with GraphQL in 2021?

- Apollo released [Odyssey](https://odyssey.apollographql.com), a series of free tutorials for learning GraphQL that’s appropriately named (and styled) to keep up with Apollo’s *Ancient-Greeks-in-space* branding.
- The Guild released [Envelop](https://www.envelop.dev), a plugin system that makes it easier to add features and integrations to GraphQL servers.
- The GraphQL Foundation published the [2021 Spec](https://spec.graphql.org/October2021/) — a very long document that (like the book *Infinite Jest*) no one has [actually read](https://mobile.twitter.com/miragonz/status/983057575972192256) in its entirety. But it’s still a great resource.
- v16 of [GraphQL-JS](https://github.com/graphql/graphql-js/releases/tag/v16.0.0) (the reference implementation of GraphQL that everyone uses) was released. They *finally* kicked Flow to the curb and rewrote the entire thing in TypeScript 🙏.

**We kicked off 2022 in style** with the release of [Relay 13.0](https://github.com/facebook/relay/releases/tag/v13.0.0), which includes their fancy new [Rust compiler](https://relay.dev/blog/2021/12/08/introducing-the-new-relay-compiler/) (because every OSS project is legally required to rewrite their compiler in Rust now).

Relay is Meta’s GraphQL client of choice. It only works if your GraphQL server [follows the Relay specification](https://relay.dev/docs/guides/graphql-server-specification/), but it promises [declarative](https://www.youtube.com/watch?v=E7Fbf7R3x6I) data fetching, query optimization, and less boilerplate. This new Rust compiler, along with the cutting-edge [React hooks API](https://relay.dev/blog/2021/03/09/introducing-relay-hooks/) they released last year makes Relay a compelling option — especially if you’re building a [dystopian Wal-Mart hellscape](https://twitter.com/DigitalisHomo/status/1478094074909540354) in the metaverse.

**Bottom Line:** It looks like GraphQL stock will continue to go up-and-to-the-right in 2022 (unlike literally every single real stock).
