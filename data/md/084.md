## Remix vs Next.js — The Showdown

**Let’s get ready to rumble…** Remix threw down the gauntlet last week with a [6,700 word essay](https://remix.run/blog/remix-vs-next) on why they’re better than Next.js. It’s well-written but super long, so we made this [13-second video summary](https://video.twimg.com/ext_tw_video/1424050741778403333/pu/vid/360x360/2AdfLnYANcS80PQk.mp4?tag=12) for you.

**How We Got Here:** Remix is a React meta-framework that’s SSR-only and was created by the folks behind React Router. It’s “edge-first,” able to deploy anywhere, and has gotten [lots of hype](https://twitter.com/jaffathecake/status/1483706092215586816?s=20) since it launched v1 in November.

**But how is that different from Next.js?** Turns out, the Remix team was tired of literally everyone asking that question, so the article uses lots of nuanced measurements to directly compare a Next.js app and a Remix app. From there, they shared the following scientific conclusions:

- Remix is faster
- Next.js is slower
- Remix’s dad could beat up your dad

**[HOW?](https://www.youtube.com/watch?v=W-TGdhurBdU)** The Remix app server-rendered every single page, instead of using SSG. They could do this faster than Next.js because they cache their data “at the edge” with a Redis database and also run their servers “at the edge.” (Not everyone agrees on what “the edge” [actually means](https://twitter.com/crim_codes/status/1484594510483054592?s=20), but just imagine servers close to users.)

**But at what cost?** Is “best-in-class performance” really worth it if you have to run a distributed server *and* a distributed database *and* a Redis cache? That Remix example even included a [Docker Compose file](https://github.com/jacob-ebey/remix-ecommerce/blob/main/docker-compose.yml) — and now I’ve got Egghead pushing [Docker courses for Remix devs](https://twitter.com/eggheadio/status/1484548808742563841?s=20) on my timeline. At least we all got our Master’s Degrees in Distributed Systems, right? 💀

**Remix *is* on to something, though** — hosting sites closer to users does provide a better experience, and Vercel knows it too. Soon, Vercel will follow Remix over the edge by providing [edge-rendered sites](https://twitter.com/leeerob/status/1484340768290471936), thanks to their new Edge Functions feature (AKA two Cloudflare Workers in a [trench coat](https://www.youtube.com/watch?v=D1RgdMLbx3M)). All the speed and flexibility of edge-rendering *without* all the extra infrastructure sounds pretty nice right now.

**Bottom Line:** When frameworks compete, [developers win](https://twitter.com/leeerob/status/1465702417513680897). When frameworks have raised mountains of VC cash, they tend to compete a little harder. Personally, I’m still just waiting for [this livestream](https://twitter.com/mjackson/status/1459656714362310658?s=20) to happen.

## TypeScript 4.6

TypeScript just announced its v4.6 beta — but unlike our last story, they didn’t even write a blog post calling out one of their rivals by name (boring). Hopefully they’ll fire up the hot take machine soon and write that scorching “TypeScript vs. Flow” blog post we’ve all been waiting for (since 2014).

In the mean time, there are *a lot* of [new features and improvements](https://devblogs.microsoft.com/typescript/announcing-typescript-4-6-beta/) in TypeScript 4.6. Will you notice most of them? Probably not, but here’s the highlights:

- TypeScript now warns you about more errors, like duplicate `const` statements or using a static `import` inside a function.
- If you’re writing extended classes, you can now write code *before* calling `super()`. Previously, you couldn’t include any code before `super()`, since you needed to call `super()` before accessing `this`. We warned you this would be dry but here you are, still reading - good on you.
- TypeScript has better performance when doing recursive type checks, like with types that appear to be infinitely nested inside themselves.
- There’s better type inference and type checking when working with indexed access types and dependent parameters. We don’t know what that means either but hey I’m sure it’s great.

**Bottom Line:** It’s another solid release for TypeScript — but Zuck just told me that Flow already had all these exact same features years ago. I guess it’s time for him and Satya to take a page out of the *Remix vs. Next.js* playbook and settle this once and for all… by writing long blog posts and subtweeting each other while pretending they’re on the same team.

## Cool Bits

1. There’s a new [Chrome DevTools feature](https://developer.chrome.com/docs/devtools/recorder/) that lets you record, replay, and measure user flows. I can’t tell if this feature will replace 50% of a product manager’s work, or result in 50% more product managers getting hired. Probably both.
2. Kyle Simpson (AKA Getify AKA Mr. LinkedIn) wrote an [Expansive Intro to Monads](https://github.com/getify/monio/blob/master/MONADS.md#fp--monads). After reading it, you’ll probably still have some questions, like *What are Monads?* and *Is that even a real word?* But I’m pretty sure that’s the point — *no one* knows what it means, but it’s provocative. It gets the people going.
3. [TinyBase](https://tinybase.org/) is a new, “smarter way” to structure your application state with a more database-like approach. If this thing catches on they may even get their own “Remix vs TinyBase” hit piece.
4. [Deno 1.18](https://deno.com/blog/v1.18) was just released, and it comes with a fancy new Web Cryptography API. If you’re confused about what a *Web Cryptography API* is, please re-read the last sentence of Cool Bit #2 for an explanation.
5. Orta Theroux (from the TypeScript team) created 4 helpful-looking [TypeScript cheat sheets](https://www.typescriptlang.org/cheatsheets). But if the professor catches you using them on the midterm, you DID NOT get them from me, ok? I need this class to graduate.
6. [Simple.css](https://github.com/kevquirk/simple.css) is a classless CSS template that lets you make good looking websites quickly. Now all you need to do is add a few gradients, upgrade to Deno 1.18 for the Web Cryptography API, get your recursive type checks going with TypeScript 4.6, throw in a few Monads (sounds right), and migrate to Remix — along with its requisite distributed server, distributed database, Redis cache, and Docker Compose File. Then, you’ll finally have a *simple*, modern web site for your personal blog. Was that so hard?
7. [Dioxus](https://dioxuslabs.com/blog/introducing-dioxus/) is a new Rust framework for building UI’s that’s heavily inspired by React. Because there are only three guarantees in life: Death, Taxes, and Rust. Salad Fingers tried to warn us.
