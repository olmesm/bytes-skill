### React’s very own programming language

As a kid, remember when you’d start losing and instead of finish the game, you’d just quit and go play by yourself?

That’s kind of what happened with Flow, Meta’s type-safe programming language. It first launched back in 2014, but shifted to being an [internal Meta project](https://medium.com/flow-type/clarity-on-flows-direction-and-open-source-engagement-e721a4eb4d8b) a few years later after losing out to TypeScript. Thankfully, there were slightly less tears than when my brothers used to beat me at Three Flies Up 🙏.

But there’s a silver lining – by focusing solely on Meta’s needs, Flow has been able to create some interesting [language features for React](https://medium.com/flow-type/announcing-component-syntax-b6c5285660d0) that wouldn’t work for more general-purpose languages like TypeScript.

Flow refers to these features as [Component Syntax](https://flow.org/en/docs/react/component-syntax/), consisting of three new keywords designed to make it easier to write high-quality React code:

- `component` – Replaces the `function` keyword and lets you define components in way that reduces boilerplate and enforces the [Rules of React](https://react.dev/reference/rules)
- `hook` – Also replaces `function` when declaring custom hooks and makes sure your hooks adhere to React’s programming model
- `renders` – Gives you a simple way to enforce design systems by expressing stylistic constraints through types

**Bottom Line:** Meta has already adopted Component Syntax across all of their codebases, so if you’re a React dev that’s feeling a little bit of Flow Envy™️ right now, just try getting a job at Meta. That might sound hard, but it’s definitely easier than convincing your current employer to migrate to Flow.

### [Convex just went open source](https://news.convex.dev/convex-goes-open-source/) 👀

Their backend-as-a-service platform gives you a realtime database, server functions, and a set of client libraries to replace all your glue code – and it’s now open source 🥳.

**What does that mean?** The [Convex GitHub repo](https://github.com/get-convex/convex-backend) now has over 200,000 lines of Rust and TypeScript code, comprising its core backend and the server-side function environment.

This unlocks some exciting new ways to use Convex:

- **Local development** for testing or building offline with lower latency and faster push times ([see guide](https://stack.convex.dev/developing-with-the-oss-backend)).
- **Self-hosting** so you can run it yourself in production.
- **Transparency** so you can learn about [how Convex works under the hood](https://stack.convex.dev/how-convex-works), and see if it fits your team’s needs.

[Clone the repo](https://github.com/get-convex/convex-backend?tab=readme-ov-file#getting-started) to get started, and check out this episode of [the Software Engineer Daily Podcast](https://softwareengineeringdaily.com/2024/03/20/going-open-source-at-convex-with-james-cowling/) where Convex’s CTO breaks down *everything* that went into open-sourcing their backend platform.

## Spot the Bug: Solution

#### Sponsored by [New Relic](https://newrelic.com/blog/how-to-relic/first-gen-ai-chatbot?utm_source=bytes&utm_medium=community&utm_campaign=global-fy25-q1-first-gen-ai-chatbot)

```
function deepCopy(obj) {
  return JSON.parse(JSON.stringify(obj))
}

const user = {
  name: 'Tyler',
  age: 32,
  created: new Date()
}

const copiedUser = deepCopy(user)
```

A deep copy of an object is a copy whose properties do not share the same references as those of the source object from which the copy was made. One approach for deep copying in JavaScript is using `JSON.stringify` and `JSON.parse`.

This kind of works in our case, but it will convert `created` to a string. To prevent that, you can use `window.structuredClone` instead (assuming browser support).

```
function deepCopy(obj) {
  return window.structuredClone(obj)
}
```
