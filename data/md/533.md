### TypeScript Can Read Your Weird Files:

What happens when you give a bunch of millennial JavaScript developers White Monsters, gas station Tornados, and access to the internet? They’re going to try and stick their JavaScript into every imaginable type of file, which explains why `.jsx`, `.mdx`, `.astro`, `.svelte`, and `.vue` exist.

But as we “matured” into TypeScript developers, this created a bunch of problems. In order to type check these random file types, you either needed to wrap the compiler and ship something like `vue-tsc` or use a project like `@volar/typescript` to build a language server for your project. That was until [TypeScript 7.1 beta shipped this past week](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/), which introduced a new feature called Content Mappers.

**What are content mappers?**

Content mappers are a new type of plugin that teaches TypeScript how to translate an arbitrary file type into a virtual TypeScript file that the type checker can use. It’s what powers [`reylo`](https://reylo.dev/)’s type inference for `.sql` files.

*Here’s how they work:*

- **Register a mapper:** Content mappers are added via `tsconfig.json` and specify the file extensions they are designed to handle. They are then executed by running `tsc --runExternalCode`.
- **Transform the source:** The mapper converts matching files into virtual TypeScript files with references to the original source. If you’re code curious, [here’s an example for HTML](https://github.com/DanielRosenwasser/content-mapper-sample/blob/main/dhtml-content-mapper/src/html.ts).
- **Check the types:** TypeScript checks the virtual files and uses span mappings to report errors at the correct locations in your original file. These mappings also enable code completions, hover hints, and click-to-definition navigation (if anyone still uses their IDE).

**Bottom Line:** Content mappers are TypeScript’s midlife crisis marathon: you atone for the sins of your past, but it’s maybe a few years too late for it to really matter 🫠.

## Spot the Bug: Solution

#### Spot the Bug – Sponsored by [Jam](https://jam.dev/mac?utm_campaign=mac-launch&utm_source=bytes)

The URL only contains `tag=ts`. `URLSearchParams.set()` replaces the previous value for a key, so the second tag overwrites the first. Use `append()` to keep both values:

```
function buildSearchUrl(tags) {
  const params = new URLSearchParams();
  tags.forEach((tag) => params.append("tag", tag));
  return `/search?${params}`;
}

console.log(buildSearchUrl(["js", "ts"]));
```
