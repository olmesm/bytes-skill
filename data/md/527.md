### Ready to Remiiix

One year ago, our dads Ryan Florence and Michael Jackson got up on stage at Remix Jam and revealed ~~Angular 2.0~~ Remix 3, starting their crusade against React, build tools, and all the unnecessary complexity we’ve come to accept as web developers. But a lot can change in a year.

For starters, one of the more notable announcements from [this year’s Remix Jam](https://remix.run/jam/2026) was that Ryan is no longer with the team. And in fairness, if I had to sell React developers on `this.update()`, I’d probably quit too. But this year, the main topic of conversation wasn’t the component model, it was everything else.

**A full-stack JavaScript framework… finally?:**

One of the great mysteries in the JS hellscape we have lived in for most of our careers is why a Rails- or Laravel-style full-stack JavaScript framework has never taken off. This is what Remix 3 is trying to be – a truly full-stack framework. “For most web apps, `remix` can be the only runtime dependency in `package.json`.”

Here’s what comes out of the box with Remix 3:

- **HTTP Server:** Remix provides a type-safe router, controllers, and middleware using the same building blocks as your front-end code: `Request` and `Response`.
- **Auth:** Remix handles sessions and login providers, while middleware resolves identity and protects routes.
- **Data:** We all know front-end devs shouldn’t database, but Remix 3 provides a built-in type-safe ORM that can connect to Postgres, MySQL, or SQLite with a Zod-like schema validator.
- **Assets:** The Remix asset server can compile TypeScript, JavaScript, and CSS on demand, transform files on the fly, and serve them as native browser modules with import maps. During development, code hot reloads instantly.
- **UI:** The Reactless utopia dozens of developers yearn for is finally here with Components, Frames, styles, animations and a built-in UI library.

**Bottom line:** There has been a lot of debate on whether or not we need frameworks like Remix anymore, but last time I checked tokens aren’t free (yet), so I’m happy to let Shopify burn them on my behalf.

## Spot the Bug: Solution

#### Spot the Bug - Sponsored by [Apify](http://apify.com/integrations/lovable?fpr=fireship)

The `calculateTotal` method changes the cached data in place, so the “before tax” price becomes 120 instead of staying at 100. Return a new object with new item objects to keep the original data intact.

```
const mockAPIData = {
  items: [
    { id: 1, price: 100 },
    { id: 2, price: 200 }
  ]
};

class DataCache {
  constructor() {
    this.cache = new Map();
  }

  getData(key) {
    if (!this.cache.has(key)) {
      this.cache.set(key, mockAPIData);
    }
    return this.cache.get(key);
  }

  calculateTotal(data) {
    const newData = {
      items: data.items.map(item => ({
        ...item,
        price: item.price * 1.2
      }))
    };
    return newData;
  }
}

const cache = new DataCache();
const data = cache.getData('products');
const withTax = cache.calculateTotal(data);
console.log('Before tax calculation:', data.items[0].price);
console.log('With tax:', withTax.items[0].price);
```
